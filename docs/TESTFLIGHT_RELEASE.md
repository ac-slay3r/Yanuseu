# Yanuseu TestFlight setup — new VYJS7JMXU5 app

**Identity:** App/repository/display name **Yanuseu**; new iOS Bundle ID **`cool.n0thing.yanus`**; Apple Developer Team **`VYJS7JMXU5`**. AC requested a fresh Apple app record while reusing Yanuseu's working codebase. Neither the App ID nor App Store Connect record is independently confirmed yet. The earlier `cool.n0thing.yanuseu`/`2CH5J3W7UH` signing material must **not** be used for this release. Changing the Bundle ID makes a distinct iOS installation; its Keychain, preferences, and local chat history do not automatically migrate.

## Register the new app on the correct team

1. Sign in to [Apple Developer → Certificates, Identifiers & Profiles](https://developer.apple.com/account/resources/identifiers/list) with Team **`VYJS7JMXU5`** selected. In **Identifiers → + → App IDs → App**, register an **explicit** App ID `cool.n0thing.yanus` (not `cool.n0thing.yanuseu`). Keep capabilities minimal; Yanuseu currently has no extension or special entitlement. If Apple says the ID is unavailable, stop—do not silently alter the token.
2. In [App Store Connect → Apps](https://appstoreconnect.apple.com/apps) with the **same team**, create a new iOS app named **Yanuseu**, selecting the exact `cool.n0thing.yanus` Bundle ID and a unique SKU. Do not create a Hermes dashboard app or reuse an old app record. Record the app's ASC ID when available; no record ID is assumed here.
3. The existing Apple Distribution certificate for **`VYJS7JMXU5`** is valid and its private key is already held on the Linux release host. In [Profiles](https://developer.apple.com/help/account/provisioning-profiles/create-an-app-store-provisioning-profile/) → + → Distribution → **App Store Connect**, select new App ID `cool.n0thing.yanus` and that VYJS certificate, then download its `.mobileprovision`. The old `2CH5J3W7UH` profile is invalid for this app. Add its single-line base64 to `YANUSEU_APP_PROFILE_BASE64` through Yanuseu GitHub Actions Secrets; do not send it in chat.
4. In App Store Connect → Users and Access → Integrations → **App Store Connect API**, select Team `VYJS7JMXU5` and create a Team API key with **Developer** access for upload. Add its *actual* Key ID, Issuer ID, and complete downloaded `.p8` in GitHub Actions Secrets as `ASC_API_KEY_ID`, `ASC_API_ISSUER_ID`, and `ASC_API_PRIVATE_KEY_P8`. Team ID is not a Key ID. Do not send private keys, passwords, or one-time codes in chat.
5. Review App Privacy, export compliance, TestFlight beta description/contact, age rating, and tester groups based on the actual direct-to-selected-provider data flow. Never guess encryption or privacy answers.

## Release boundary

The verified VYJS distribution certificate and its password have been placed in repository secrets `APP_DISTRIBUTION_P12_BASE64` and `APP_DISTRIBUTION_P12_PASSWORD`; the secret names were read back, not their values. **Do not dispatch a release until the new App ID and ASC record exist and the matching provisioning profile plus API credentials are set.** The manual GitHub Actions workflow accepts only a current green `main` SHA, verifies Team/Bundle ID/profile/signature, then validates/uploads. Upload success is **not** TestFlight availability: inspect App Store Connect processing and tester access before announcing a beta. Follow [BETA_TESTING.md](BETA_TESTING.md) for physical-device and live-provider acceptance. No signed archive or upload for `cool.n0thing.yanus` has been verified yet.
