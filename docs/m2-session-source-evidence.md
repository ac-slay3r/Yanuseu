# M2 session slice: source evidence and iOS boundaries

Hermes reference checkout: `95f4b45c32b9a4ec1f4a794af54feb0c676c06c4` at `/home/aconn/.hermes/hermes-agent`.

- Hermes lists recent sessions with profile filtering and treats storage failures as errors, not empty histories (`hermes_cli/web_routers/sessions.py:163–241`; `hermes_state_sessions.py:1168–1187`). Yanuseu uses a local, profile-filtered `ConversationStore`; it does **not** call that API or require a gateway.
- Hermes resolves a stored session through its compression chain before resuming a runtime (`hermes_state_messages.py:687–726`; `tui_gateway/methods_session.py:594–626,787–818`). Yanuseu has no compression chains: selecting a local conversation ID makes its saved messages the active on-device context for the next foreground turn. No desktop runtime is resumed.
- Hermes searches session IDs and message content, with lineage-aware deduplication (`hermes_cli/web_routers/sessions.py:254–264,283–328,361–387`). Yanuseu searches the selected profile's local titles and message bodies only. It does not implement FTS, global session search, or model-facing memory recall.
- Hermes distinguishes storage corruption from an authoritative empty result and recovers to a separate output rather than silently replacing the active database (`hermes_state_errors.py:18–55`; `hermes_cli/session_recovery.py:1067–1092`). Yanuseu's JSON store fails closed on unreadable data. After explicit user confirmation it moves the original bytes to a local archive and creates a new empty history. The archived bytes can be exported through a user-initiated iOS share sheet, but this is **not** JSON repair, partial salvage, or a promise that the archived content is readable. The archive is file-protected and excluded from backup by its parent directory. Physical-device recovery remains to be tested.

The M2 completion slice stores a legacy-safe `isArchived` flag on each local conversation. The ordinary list/search hides archived sessions; the Archived Sessions view permits unarchive, resume, export, rename, and delete. This is distinct from the unreadable-byte recovery archive. Recovery now writes a protected marker before moving the unreadable file; a restart after the move blocks ordinary history writes until the pending archive is protected and a fresh history is saved. The interrupted-recovery restart path is covered by a deterministic store test, not a physical-device claim.
