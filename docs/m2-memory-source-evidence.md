# M2 local memory: Hermes evidence and native boundary

Hermes source checkout `959c7649fd806c3996cdd845ee4bd4e0eb1a0276` at `/home/aconn/.hermes/hermes-agent` (read-only). The session evidence at `docs/m2-session-source-evidence.md` pins a different earlier revision.

- Built-in `MEMORY.md` and `USER.md` are loaded into a snapshot (`tools/memory_tool_store.py:133–164`) and rendered into the system prompt (`tools/memory_tool_store.py:463–489`; `agent/system_prompt.py:515–540`). Yanuseu instead stores explicit, profile-scoped user-entered notes in protected local app storage and snapshots their text for each foreground turn. It does **not** read desktop Hermes memory files or require a Hermes host.
- Hermes `replace` updates an entire matched entry; `remove` deletes it (`tools/memory_tool_store.py:298–316,344–361`). Staged edits pin the reviewed entry and reject stale matches (`tools/memory_tool.py:64–81`; `tools/memory_tool_store.py:318–325`). Yanuseu uses stable note IDs and checks the selected profile for edit/delete; only saved future turns receive corrected notes.
- Built-in Hermes memory files hold entry text, not per-entry provenance (`tools/memory_tool_store.py:1–4,210–212,510–528`). External mirror metadata is built separately (`agent/background_review.py:739–754`). Yanuseu labels every local note as **Added by you**; it does not attribute notes to the agent or imply automatic extraction.
- A Hermes session can retain its frozen system-prompt memory after a write; compression invalidation reloads it (`tools/memory_tool.py:2–5`; `agent/conversation_loop.py:721–725,770–795`; `agent/system_prompt.py:790–820`). Yanuseu intentionally refreshes local memory at **each new foreground turn** and holds that snapshot through all tool-continuation requests. Editing a note does not change an in-flight request, an earlier provider request, or persisted transcript.
- Hermes refuses unreadable memory and destructive external drift rather than replacing it silently (`tools/memory_tool_store.py:245–274,491–544`). Yanuseu blocks requests when local memory is unreadable; the in-app memory screen exposes retry. It does not offer automatic salvage or a remote memory backend.

Memory has a bounded total turn budget and does not grant tools. The note editor, `/memory` command, provider payload, and profile-isolation tests are part of the same usable slice. No background execution, arbitrary files, shell, or automatic memory writer was added.
